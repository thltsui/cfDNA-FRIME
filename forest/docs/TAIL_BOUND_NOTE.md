# Research note — adapted Lyapunov lookback bound

**Date:** 10 September 2026  
**Status:** mathematical candidate for review; not implemented in `certificate.py`.

## Purpose

The current certificate uses the single family weight `h_p(x)=(x/ell)^p`. It is
valid but can have a very large prefactor because `h_p(L)` grows like `(L/ell)^p`.
This note derives a more flexible additive Lyapunov weight that preserves the same
Poisson-history coupling and inherited-exit model while adapting to the actual exit
profile.

## General additive-weight certificate

Let `C_x(t)` be one FRIME immigrant family, and let

$$V_h(C)=\sum_{x\in C}h(x),$$

where `h(x)>=1` for retained sizes `x>ell`. If for some `kappa>0`,

$$
\rho(x)\left(\mathbb E[h(xR)1_{xR>\ell}+h(x(1-R))1_{x(1-R)>\ell}]-h(x)\right)
-E(x)h(x)\le -\kappa h(x)
$$

for every `x in (ell,L]`, then Dynkin + Gronwall gives

$$\mathbb E[V_h(C_x(t))]\le h(x)e^{-\kappa t}.$$

A nonempty family has `V_h>=1`, hence

$$\Pr(\tau_x>t)\le h(x)e^{-\kappa t}.$$

For uniform immigration on `[0,L]`, define

$$\bar h=\frac1L\int_\ell^L h(x)\,dx.$$

Then the omitted-old-family intensity satisfies

$$\Lambda_T\le \frac{C_I\bar h}{\kappa}e^{-\kappa T},$$

so the same common-driver mismatch/path bound in `MATHEMATICS.md` applies. The
existing p-mass certificate is the special choice `h=(x/ell)^p`.

## Uniform splits, alpha = 1

For `R~Uniform(0,1)` and `rho(x)=C_F x`, set

$$H(x)=\int_\ell^x h(y)\,dy.$$

Then

$$\mathbb E[h(xR)1_{xR>\ell}+h(x(1-R))1_{x(1-R)>\ell}]
=\frac{2H(x)}x.$$

The Lyapunov condition reduces to

$$2C_FH(x)\le [C_Fx+E(x)-\kappa]h(x).$$

For fixed `kappa`, the minimal candidate with `h>=1` is generated by

$$H'(x)=h(x)=\max\left\{1,\frac{2C_FH(x)}{C_Fx+E(x)-\kappa}\right\},
\qquad H(\ell)=0,$$

provided the denominator stays positive. Where the second branch is active, the
drift inequality is an equality. This is a one-dimensional Volterra/ODE problem,
not a simulation-tail estimate.

## Benchmark PFB calculation

Use the existing benchmark:

`L=1, ell=.02, C_F=2, alpha=1, C_I=100, a=b=1, B=.4, beta=-1, c_e=1`.

Thus

$$E(x)=\begin{cases}x^{-1}-B^{-1},&x<B,\\0,&x\ge B.\end{cases}$$

Take `kappa=0.72`. The `h=1` branch ends at the positive root of

$$4(x-\ell)=2x+E(x)-0.72,$$

namely `x0 ≈ 0.2715154992`. For `x>x0`, solve

$$\frac{H'(x)}{H(x)}=\frac4{2x+E(x)-0.72},\qquad H(x0)=x0-\ell.$$

Above `B`, `E=0`, so explicitly

$$H(x)=H(B)\left(\frac{2x-0.72}{2B-0.72}\right)^2.$$

High-precision evaluation of this analytic construction gives

`H(L)/L = bar_h ≈ 356.53609375`.

Therefore

$$T=\frac1{0.72}\log\left(\frac{100\,\bar h}{0.72\times10^{-6}}\right)
\approx 34.2023.$$

Using `T=34.21` gives the numerical upper bound `Lambda_T≈9.94e-7`. The current
p-mass certificate reports `T≈70.07`. Thus this adapted weight cuts the certified
lookback by about 51% for the benchmark before any simulator optimisation.

## Kappa sensitivity check

Before implementation, I independently re-evaluated the ODE construction and
optimised the resulting sufficient lookback over feasible `kappa`. For this PFB
model the denominator `2x+E(x)-kappa` is positive over the retained interval only
for `kappa<0.8`; approaching `0.8` makes the weight explode near the exit boundary.

A one-dimensional numerical minimisation gives

`kappa* ≈ 0.7262776`, `bar_h ≈ 441.3875`, `T ≈ 34.18862`.

The original deliberately chosen `kappa=0.72` gives `T≈34.20225`, only about
`0.014` time units longer. Hence there is essentially no practical benefit in
optimising kappa aggressively. Representative values are:

| kappa | bar_h | certified T |
|---:|---:|---:|
| 0.68 | 126.83 | 34.78 |
| 0.70 | 200.73 | 34.40 |
| 0.72 | 356.54 | 34.20 |
| 0.72628 | 441.40 | 34.19 |
| 0.74 | 760.97 | 34.27 |
| 0.76 | 2277.01 | 34.77 |
| 0.78 | 15659.77 | 36.32 |

This also exposes the numerical danger of choosing kappa too near the theoretical
ceiling: a slightly faster exponential rate is more than offset by a rapidly
inflating prefactor. A production implementation should therefore use a robust
bounded search or a conservative fixed/adaptive candidate set, and explicitly
reject denominators that approach zero.

The mathematical construction above is exact. Decimal evaluations were checked by
independent root finding, quadrature and scalar optimisation in double precision;
they are not formal interval-arithmetic certificates. Production code should retain
the numerical caveat already documented for the current float64 certificate, or
add outward interval bounds.

## Scope and next engineering question

This result is specific only in its cheap ODE reduction: uniform splits and
`alpha=1`. The additive-weight theorem itself is general. Non-uniform Beta splits
lead to a Volterra integral inequality rather than this simple cumulative integral.
No simulator law, exit mechanism, history-truncation interpretation, or family
independence is changed.
